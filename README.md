## Build and performance

Source modules remain in `dist/`. Run `npm ci` once, then `npm run build` after editing JavaScript and before previewing or publishing. The build bundles/minifies the game and Three.js into `dist/game.bundle.js` and updates content-hashed URLs in `boot.js` and `index.html`. The browser downloads this single bundle; source modules and the original font are retained for editing. Serve `dist/` with any static server. `npm test` checks mobile budgets, merged geometry/raycasting, retained interaction targets, and the key/shackle sequence.

Coarse-pointer, narrow-screen and low-resource devices use a 30 fps ceiling, 1.25 maximum pixel ratio (adaptive down to 0.75), one smaller shadow map, lighter chain/water geometry, and 256px procedural industrial textures. Desktop keeps a higher budget. Shadow maps and ambient effects update at separate, lower rates; camera and gameplay still update each rendered frame. Hidden tabs and completed game-over scenes stop rendering. Countdown deadlines remain based on elapsed real time.

Opaque static furniture is merged by material and spatial cell. Interactive/animated objects, transparent surfaces, and instanced creatures remain separate. Shared sphere geometry and packed bump/roughness/metalness maps avoid duplicate allocations. A small environment map replaces rendering the entire furnished room six times at startup. Shaders compile asynchronously while a loading message is visible, and the gothic font uses compressed WOFF.

Append `?profile=1` to a local preview to expose a hidden `#performance-report` output with startup stages, recent frame timing, draw calls and GPU resource counts. Profiling is off by default. In the desktop QA scene geometry allocations fell from 2,777 to 1,462 (47%); draw calls vary with camera position and animation. Mobile viewport checks exercise the reduced budget but do not substitute for testing physical phones on slow networks.
